# rules/common.md — 通用开发规范

> 所有操作的基础规则，无论角色分工。

---

## 操作前确认

1. **每次操作前确认工作区状态**
   - `pwd` 确认当前位置
   - `git status` 确认 git 状态
   - 有未保存更改时，先确认是否需要提交

2. **危险操作前停顿**
   - `rm`、`trash`、删除文件前确认目标
   - 目标不明确时，先 `ls` 确认

---

## Git 规范

1. **commit 前检查 diff**
   - `git diff` 或 `git diff --staged` 确认变更内容
   - 不要盲目 `git add -A`

2. **commit message 规范**
   - 第一行：简短总结（50字以内）
   - 第二行：空行
   - 第三行起：详细说明（如需要）

3. **push 前确认分支**
   - `git branch` 确认当前分支
   - 确认目标分支正确

---

## 文件操作

1. **不要 `rm -rf` 不确认**
   - 除非明确知道自己在干什么
   - 用 `trash` 替代 `rm`（可恢复）

2. **删除前确认**
   - 删除文件：确认不是重要文件
   - 删除分支：确认已合并或不需要

---

## 外部行动

1. **外部行动先确认**
   - 发邮件、发推、公开帖子
   - 任何离开本机的操作
   - 不确定的操作

2. **执行顺序**
   - 内部行动（读文件、整理、记忆）→ 可自由执行
   - 外部行动（发消息、公开内容）→ 先确认再执行

---

## 沟通规范

1. **简洁直接**
   - 能一句说清楚的，绝不废话两句
   - 结果 > 过程说明

2. **错误诚实**
   - 出错时说明问题，不掩饰
   - 提供可行的下一步

---

_适用于所有子代理和主代理_
