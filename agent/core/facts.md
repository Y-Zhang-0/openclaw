## Skills 沉淀策略（2026-04-22 确定）

**触发条件（七字法则）：反复出现 + 容易出错 + 上下文缺失**
满足任意两个才沉淀。

| 优先级 | 条件组合 |
|--------|----------|
| 高 | 反复出现 + 容易出错 |
| 中 | 反复出现 或 容易出错（单条件） |
| 低 | 只出现1-2次 或 纯通用逻辑 |

**不沉淀**：只出现一次、我本来就能完成的、纯审美/表达性任务

**Skill复杂度选择**：
- 步骤固定 → scripts/（低自由度）
- 有模式可调 → references/（中自由度）
- 需判断触发 → SKILL.md 精准描述（中/高自由度）

## 本轮自检发现的新 Pattern（2026-04-22 晚间）

### Pattern 1: cron 配置后主动确认链路
- **来源**：用户今早自行配置了 cron，我作为 22:00 自检没有在下午之前主动确认这些任务是否生效
- **Pattern Key**: `cron-config-confirmation`
- **建议**：下次 cron 大规模修改后，在下一个运行时间点前后主动确认执行结果

### Pattern 2: 两套 cron 并存冲突
- **来源**：系统 crontab (offwork-message.sh) 和 OpenClaw cron 下班提醒重复执行
- **Pattern Key**: `dual-cron-conflict`
- **建议**：发现两套 cron 并存时主动报告用户，说明影响，让用户选择

### Pattern 3: delivery=none 的任务无法推送
- **来源**：AI资讯抓取配置为 delivery.mode="none"，导致结果推不出来
- **Pattern Key**: `cron-delivery-none-silent-failure`
- **说明**：cron delivery.mode="none" 时结果不会推送到聊天，如果需要看到结果必须改为 "announce"
- **建议**：修改 🤖AI资讯抓取 的 delivery 为 announce，或在任务链路上补一个带 announce 的转发任务
